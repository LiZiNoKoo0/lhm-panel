# 固件设计规范(SPEC)

> 版本:0.1 · 状态:草案(阶段1 重构前定稿)
>
> **效力**:本文件是"必须怎样",`ARCHITECTURE.md` 是"为什么这样"。
> 两者冲突时以本文为准;本文与 `PROTOCOL.md` 冲突时**以 `PROTOCOL.md` 为准**(协议是唯一真实来源)。
>
> **读者**:写这块屏固件的人;**以及日后拿另一块板子来移植的人** -- 第 3、9 章就是给移植者写的。
>
> 关键词:**MUST**(必须)/ **MUST NOT**(禁止)/ **SHOULD**(应该,偏离要写理由)/ **MAY**(可选)。

---

## 1. 术语

| 词 | 含义 |
|---|---|
| **底座(core)** | 与硬件无关的内核:画布、布局、值表、渲染、链路抽象、存储抽象。换板子**不许改**它 |
| **板级(bsp)** | 具体硬件:引脚、面板驱动、WiFi、flash、传感器、按键。换板子**只改**这层 |
| **布局(layout)** | 一份节点表(谁画在哪、绑哪个指标),持久化在 flash |
| **值表(values)** | `指标 id → 值 或 null`,只在 RAM,永不写 flash |
| **画面** | `compose(layout, values)` 的结果,即 160×80 的像素 |
| **应用(apply)** | PC 侧一次性提交一份新布局的动作;对应 `ui.ver` 递增 |
| **指标(metric)** | 协议 `catalog` 里的一个 id,如 `cpu.total`、`local.temp` |

## 2. 底座与板级的划分

```
core/                       ← 与硬件无关,可在 PC 上编译并单测
  canvas.rs                 画布(160x80 RGB565)+ 原语 rect/text/num/path/line
  layout.rs                 节点表(≤32 个),二进制序列化/反序列化
  values.rs                 值表、超时判定(interval_ms × 3)
  compose.rs                layout + values → 像素,脏矩形计算
  format.rs                 数值/字符串格式化(§4.5,MUST 与 PC 端逐字节一致)
  proto/                    行解析、JSON 子集、消息分发
  link.rs                   Transport trait + 重连退避 + 行缓冲
  store.rs                  KV 存储 trait + A/B 扇区算法(与 flash 无关)
  diag.rs                   错误码、计数、CRC 行、启动横幅

bsp-<board>/                ← 只实现 trait,不实现逻辑
  pins.rs                   引脚表(含预留,见 §3.7)
  panel_<ic>.rs             panel trait 的实现(ST7735 / ST7789 / ...)
  link_uart.rs / link_tcp.rs
  store_flash.rs
  clock.rs                  单调毫秒时钟
  sensor_*.rs               可选
  input_keys.rs             可选
```

**C-1(MUST)** 依赖方向只能向内:

```
main → {compose, layout, values, canvas, link, store, diag}
compose → {canvas, layout, values, format}
canvas → 无(不许依赖 panel)
panel → 无(不许依赖 canvas)
link → 无
store → 无
```

不允许反向依赖,也不允许 `bsp` 往 `core` 里写特例。

**C-2(MUST)** `core/` 必须能在一台 x86 PC 上 `cargo test` 通过,不链接任何 ESP 库。这是"能不能移植"的唯一客观判据 -- 做不到这一条,就别声称底座可移植。

**C-3(MUST)** `core` 里出现 `esp_hal::`、引脚号、寄存器名,视为架构违规。

### 2.1 工具链与依赖事实(实测,别自己换)

| 项 | 值 | 说明 |
|---|---|---|
| `esp-hal` | `=1.1.2` | 1.2.x 要 `esp-sync 0.3`,需 esp 工具链没有的 nightly 特性 |
| `build-std` | `["core", "alloc"]` | 阶段2 起必须带 `alloc`,否则 `esp-alloc` 链不上。**`alloc` 是 no_std 合法子集,不是 `std`** |
| `esp-radio` | `0.18.0`(`wifi`, `esp32`) | `esp-wifi` 是上一代名字,停在 0.15,对新 hal 不可用 |
| `esp-rtos` | `0.3.0`(`embassy`, `esp-alloc`, `esp32`) | 三个特性必须同时开,否则 WiFi 任务起不来 |
| `esp-alloc` | `0.10.0` | 默认特性已含 `global-allocator` |
| `embassy-net` | `0.9.1`(`tcp`, `dhcpv4`, `dns`) | 通过 `embassy-net-driver 0.2` 接 `esp-radio` |
| `esp-storage` | `0.9.0`(`esp32`) | 0.10.0 要 `esp-hal 1.2`,装不上 |
| `esp-println` | `0.15.0`(`esp32`) | 不依赖 `esp-hal`,可用于 panic 输出(§7.3) |

**C-4(MUST)** 上面这些版本不许自行升降。装不上时先查是不是漏了芯片 feature(`esp32`)或 `build-std` 里的 `alloc`,而不是换版本。

## 3. 板级实现契约(移植者看这一章)

一块新板子要变成"能跑这套系统",必须提供下面六样。**缺哪个就少哪个能力,但缺前三个中的任一个就跑不起来。**

### 3.1 面板(必须)

| 契约 | 要求 |
|---|---|
| `size()` | 返回 `(w, h)`,像素为单位 |
| `pixel_format()` | 本规范只定义 `Rgb565Be`(大端)。其它格式的板子必须在 BSP 内做转换 |
| `init()` | 上电初始化,**参数写死在 BSP 里并注释实测值**(如 `MADCTL=0x60`、偏移 `(0,24)`、不反相) |
| `blit_rect(x, y, w, h, &[u8])` | 窗口写入,数据长度 MUST 等于 `w*h*2`;调用方保证不越界 |
| `blit_rect` 期间 **MUST NOT** 改窗口 | 一次窗口 + 连续写,不许中途 `set_window`(否则会出现错位半帧) |

**验收**:`blit_rect(0,0,w,h,整帧)` 之后,PC 用同一份字节算出的 CRC32 与固件报的相等。

### 3.2 链路(必须)

| 契约 | 要求 |
|---|---|
| `poll_line(&mut [u8]) -> Result<Option<usize>, LinkError>` | 取一条完整行(不含 `\n`)。MUST NOT 无限阻塞 |
| `write_all(&[u8])` | 部分写要循环写完 |
| `is_up()` | 断了要立刻变 `false` |

超长行的处理(**MUST**):超过缓冲长度就**丢弃整行直到下一个 `\n`**,计数 `E1`,不许截断后半行继续用(会产生半条 JSON)。

### 3.3 存储(必须,阶段2 起)

| 契约 | 要求 |
|---|---|
| 至少 2 个可擦除扇区(≥4KB/个) | A/B 双份,掉电可回退 |
| `read(key) / write(key, &[u8])` | 值长度上限 1KB |
| 不要求文件系统 | 手写 KV 或 `sequential-storage` 都行 |

### 3.4 时钟(必须)

单调毫秒,≥1kHz 精度,**上电从 0 开始**(不要求 RTC)。用于:值超时、折线采样节拍、重连退避、uptime。

**实现(本板,`st7735-text/src/sys.rs::now_ms`)**:`esp_hal::time::Instant::now()` 换成毫秒。
ESP32(经典)上 esp-hal 的时间源是 **TIMG0 LACT**(16MHz 计数,`rt` 启动时已配好),
不是 S3 上的 systimer。两者都满足本节要求,**按芯片走**,不要为统一去自己开 systimer。
`u32` 毫秒在上限处**静默回绕**(~49.7 天),所以时间差**只许做差、不许比大小**。

启动横幅在 `===` 行之后固定追加一行(两项,顺序与空格写死,由 `diag_format` 测试钉住):

```
heap: 65536 free=64512  clock: 5ms
```

- `heap:` = allocator 实际持有字节数,`free=` 是**探针分配仍被持有**时的剩余字节。
  所以 `free < size` 才说明分配真的成功;`free == size` 意味着探针没跑,不是"堆很健康"。
- `clock:` = 上电至今毫秒数。**它不是 0**:横幅在 `esp_hal::init()` 与 UART 配置之后才打,
  这中间已经过了几毫秒;0 只会出现在 `main` 的第一行。"从 0 开始"指**计数原点**,
  不是指横幅上的数字,也不许为了让它是 0 而减去偏移(那是伪造读数)。

### 3.5 传感器(可选)

每个传感器贡献 1..N 个 `local.*` 指标,MUST 提供:`id`、`label`(≤6 字符)、`unit`、`min`、`max`、`interval_ms`、`read() -> Option<f32>`。
读失败 MUST 返回 `None`(→ 显示 `--`),**不许返回上一次的值**。

### 3.6 输入(可选)

按键/编码器贡献 `event`。可以为空(`hello.input = []`)。

#### 3.6.1 本板:四键,内部上拉,20 ms 消抖

| 规则 | 值 | 理由 |
|---|---|---|
| 引脚 | GPIO32/33/25/26 = 上/下/确认/返回 | 都能内部上拉,不碰 strapping,不与 SPI(18/23/5/4/15/2)/UART(1/3)/I2C(21/22) 冲突 |
| 接法 | 键在 GPIO 与 **GND** 之间 | 绝不接 3V3:按下会把电源短到地 |
| 上拉 | **内部上拉使能** | 不使能时松开的键浮空,读出来是随机按键 |
| 电平 | 按下 = 低 | — |
| 消抖 | **电平保持 ≥ 20 ms 才算数** | 机械触点抖动 5–20 ms;不过滤时一次按键会让焦点跳三四格,看起来像 daemon 的连击 bug |
| 触发 | **只在 高→低 沿**,每次按下只报一次 | 按住不放不重复 |
| 上电时已按住 | **不报**,必须先松开 | 接错线/卡住不能凭空发一次谁也没按的键 |
| 轮询周期 | 渲染循环 5 ms | 比消抖窗口快 4 倍,不需要中断或定时器 |

#### 3.6.2 focus 语义(PROTOCOL §11.5 的终端侧)

| 规则 | 值 |
|---|---|
| 可选中节点 | `ui` 里带 `focusable:true` 的节点 |
| 序号基准 | **1 基**(第 1 项是 1,不是 0) |
| 顺序 | 按 `nodes` 数组顺序,不是按坐标 |
| 移动 | 上/下各移一格,**两端环绕** |
| 越界 | 收到新 `ui` 后若当前位置 > 可选中项数 → **归 1** |
| 上报 | `{"t":"event","k":"key","id":"focus","v":<序号>}` |
| 终端是否知道含义 | **不知道**。它只知道"我在第几个" |

> 环绕而不是夹紧:四个选项只有两个键时,不环绕就永远回不到第一项。
>
> 越界归 1 而不是保留:否则高亮停在一个已经不存在的按钮上,按什么都没反应,
> 而 daemon 日志一切正常——这类故障查起来最久。

### 3.7 引脚预留(本板,写死在 `bsp/pins.rs`)

| 用途 | 引脚 | 状态 |
|---|---|---|
| SPI SCLK / MOSI / CS / DC / RST / BL | 18 / 23 / 5 / 4 / 15 / 2 | 占用 |
| UART0 TX / RX | 1 / 3 | 占用(调试口常驻) |
| I2C SDA / SCL | 21 / 22 | **预留**(传感器) |
| KEY1-KEY4 | 32 / 33 / 25 / 26 | **预留**(暂不实现) |

**禁止**使用 GPIO0/2/5/12/15 做按键(strapping 或已占用);34-39 为 input-only 且无内部上拉,不做按键。

### 3.8 静态内存与栈(本板,2026-10-22 新增)

这一节不是建议,是这颗芯片的物理事实,违反后的症状会伪装成“WiFi 坏了”。

| 事实 | 值 |
|---|---|
| DRAM 区间 | `.data` / `.bss` / 堆 / 主任务栈共用一段,顶端 `0x3FFE_0000` |
| 栈的位置 | **链接器把它直接摆在 `.bss` 之后**:`栈大小 = 0x3FFE0000 - _bss_end` |
| 当前实测 | 默认构建 28,612 B;带链路泵的构建 21,868 B |

推论:**任何静态变量的增长都直接从主任务栈里扣。**

- 固件 MUST 在启动时断言栈 ≥ **16 KB**(`sys::MIN_STACK_BYTES`),并在 banner 后
  打一行 `stack: <n> bytes for the main task`。
- 固件 MUST NOT 用“为将来多留点”的理由放大静态队列/缓冲。一个方向 8 行的行队列
  就是 8,384 B `.bss` = 从栈里拿走 8 KB。
- 看门狗阈值:栈跌到 11.2 KB 时,开机、banner、屏幕全部正常,崩在 WiFi 关联里,
  panic 指向 ROM 地址(见 BACKLOG B-1)。
- 移植到其它芯片时,如果它的栈不跟 `.bss` 抢同一块内存,本节不适用;但
  “启动断言 + banner 报数”这两件事 **仍然 SHOULD 保留**。

## 4. 显示面定义(这一章是把"画成什么样"说死)

> 为什么这么较真:这块屏的验收方式是**逐字节 CRC**。
> 任何一处格式化/取整/对齐的差异,都会表现为 `PARITY FAIL`。
> 所以"差不多"在这里是**错**。

### 4.1 坐标与像素

- **D-1(MUST)** 原点在左上角,x 向右,y 向下,单位=像素,整数。
- **D-2(MUST)** 矩形区域按**半开区间** `[x, x+w) × [y, y+h)` 处理。`w=0` 或 `h=0` 表示空集,不报错。
- **D-3(MUST)** 越界像素**裁剪丢弃**,不报错、不换行、不绕回。坐标可为负。
- **D-4(MUST)** 画布内部按 RGB565 **大端**字节存(高字节在前),与 SPI 线上顺序一致;`blit_rect` 不做转换。

### 4.2 帧与 CRC

- **D-5(MUST)** RAM 里始终有一份完整的 `w*h*2` 帧(本板 25600 B)。即使只推局部,也必须维护整幅。
- **D-6(MUST)** 每次推屏后 MUST 输出一行:`FRAME <w>x<h> crc=0x<8位小写> bytes=<n>\n`,CRC 覆盖**整幅**。
- **D-7(MUST)** CRC 算法:CRC-32/IEEE(多项式 `0xEDB88320`,初值 `0xFFFFFFFF`,结果取反),与 `zlib.crc32` 同值。查表版 MUST 逐字节等价。
- **D-8(MUST)** 帧配平是**验收标准**,不是优化项:PC 端 `check_parity.py` 报 `PARITY OK` 才算通过。

### 4.3 布局与节点

- **D-9(MUST)** `nodes` 数组**顺序即绘制顺序**,后者覆盖前者。
- **D-10(MUST)** 未知 `type` **静默忽略并计数 `W2`**(协议 §20 向前兼容),MUST NOT 断开链路。
- **D-11(MUST)** 节点数超过 `max_nodes`(32)时,**保留前 32 个**并计 `W3`;不许整页丢弃。
- **D-12(MUST)** `bind` 指向的指标不存在、为 `null`、或已超时 → 该节点照常绘制,但值渲染为 `--`。
  **不许跳过该节点**--节点消失会让整个布局跳动,比显示 `--` 更糟。
- **D-13(MUST)** 第一版最小原语集:`rect` / `text` / `num` / `path`。语义控件 `line` 见阶段4。
  `bar` / `dot` 等未声明在 `hello.widgets` 的类型一律按 D-10 忽略。

### 4.4 文本

> **字号(T6 之后)**:`size` 取 `hello.fonts` 里的值,其余由 PC 侧 `fit_nodes`
> 就近改写成合法值;固件侧再兜一次(取最近的)。本板 16 是原生 8×16,32/48 是
> **整数倍像素放大**:每个置位像素画成 `k×k` 块。
>
> **不做非整数倍**(如 1.5×):8 像素高的字形里有的像素要翻倍有的不翻,看上去像
> 字模坏了,而不像"小一号"。

| # | 规则 |
|---|---|
| D-14 | 字形:8×16 单色点阵,95 个可打印 ASCII(0x20-0x7E)。最高位=最左像素,1=墨 |
| D-15 | 字符集 `ascii`:输入出现非 ASCII 字节 → 该字符渲染为 `?`,计 `W4` |
| D-16 | 字模表里缺失的字形 → `?` |
| D-17 | **不自动换行、不折行**。排版是 PC 的事 |
| D-18 | 超过 `max_text_len`(20 字符 = 160px)→ 保留前 19 个,第 20 个渲染为 `>` |
| D-19 | `align`:`left`(默认)/ `center` / `right`,相对节点 `x` 计算;`center` 向**左**取整 |
| D-20 | 行高 = 16px,字宽 = 8px,字间距 0,行间距 0 |

### 4.5 数值渲染(`num`)-- 最容易各写各的,必须照抄

| # | 规则 |
|---|---|
| D-21 | 值 `null` / 缺失 / 超时 → **`--`**(两个半角连字符 `0x2D 0x2D`,不是破折号、不是 em dash、不是 `N/A`) |
| D-22 | `dec` 小数位,**四舍五入,half away from zero**(`33.45` → `33.5`,`-7.5` → `-8`) |
| D-23 | 取整后为 0 且原值为负 → **去掉负号**(禁止输出 `-0`、`-0.0`) |
| D-24 | 小数点固定 `.`,**不随 locale 变**;不用千位分隔符 |
| D-25 | `unit` 紧贴数字,**中间不加空格**(`33.5%`、`34C`) |
| D-26 | **不夹紧**到 `min`/`max`。超范围就显示真值(夹紧等于撒谎);要提示就改颜色(阶段4) |
| D-27 | `dec` 缺省 0;`dec > 3` 按 3 处理并计 `W5` |
| D-28 | `type: "string"` → 原样显示,超 20 字符按 D-18 截断 |
| D-29 | `type: "bool"` → `ON` / `OFF`(大写,各 2/3 字符) |

**Golden 测试向量(MUST 两侧共跑)** `firmware/testdata/num_format.csv`:

| value | dec | unit | 期望输出 |
|---|---|---|---|
| `null` | 1 | `%` | `--` |
| `33.456` | 1 | `%` | `33.5%` |
| `33.44` | 1 | `%` | `33.4%` |
| `33.45` | 1 | `%` | `33.5%` |
| `-0.04` | 1 | `C` | `0.0C` |
| `-0.4` | 0 | `C` | `0C` |
| `7.5` | 0 | | `8` |
| `-7.5` | 0 | | `-8` |
| `0.5` | 0 | | `1` |
| `12` | 2 | | `12.00` |
| `999.95` | 1 | | `1000.0` |
| `100` | 0 | `%` | `100%` |

> 表里没有的情形**不要自己发挥**:先补一行到 CSV,两侧同时改,再提交。

### 4.6 颜色

| # | 规则 |
|---|---|
| D-30 | 输入格式 `#RRGGBB`(6 位十六进制,大小写均可) |
| D-31 | 量化:`R5 = R>>3` / `G6 = G>>2` / `B5 = B>>3`(**截断,不四舍五入**);结果按大端组成 `u16` |
| D-32 | 量化带来的颜色差异**不报错、不警告**。但 PC 端预览 MUST 用同一条量化式,否则 CRC 不一致 |
| D-33 | `#000000` 即背景色;`bg` 缺省为 `#000000` |

### 4.7 重建 vs 增量

| # | 规则 |
|---|---|
| D-34 | 收到 `ui` 且 `ver` **≠** 当前 `ver` → **整页重建**(重新排布节点)。判据是 `!=`,**不是 `>`** |
| D-35 | 收到 `ui` 且 `ver` **==** 当前 `ver` → 跳过结构重建(协议 §7),但仍 MUST 刷新值 |
| D-36 | 收到 `data` → **只更新 bind 到这些指标的节点**,MUST NOT 整页重绘 |
| D-37 | 重建后 MUST 清屏(铺 `bg`)再画,避免残留 |
| D-38 | 切换 `scene`:板上只保留**当前页**一份布局(≤32 节点)。翻页由 PC 发新 `ui` 完成,板上不做页面栈 |

### 4.8 脏矩形与推屏

| # | 规则 |
|---|---|
| D-39 | 每次渲染前清空脏区记录;一个节点被改动,就把它的完整外接矩形记脏 |
| D-40 | 同一帧内多个脏区 → **合并为一个最小外接矩形**(第一版就这么简单,不做多矩形) |
| D-41 | 脏区覆盖 ≥60% 屏面积,或发生整页重建 → 直接整帧 `blit_rect(0,0,w,h)` |
| D-42 | 只推脏区时,MUST 仍然更新整幅 RAM 帧(D-5),CRC 仍算整幅(D-6) |
| D-43 | 单次 `blit_rect` 的 SPI 时间 SHOULD ≤ 4ms(本板 20MHz 下约 8KB);超了就说明脏区太大,考虑整帧 |

### 4.9 无值 / 无布局 / 掉线

| 情形 | 屏上必须是什么 |

| 有布局、有值 | 正常画面 |

| 有布局、链路断 | 画面**保持不动**,只叠 `LINK LOST` 角标;**禁止清屏、禁止黑屏**(协议 §13.5) |

| 复位瞬间 | 屏不做处理(面板会被重新 init);串口 MUST 留一行复位原因 |

> 画的东西**,而它最危险的故障不是“不出现”(看得见)而是“不消失”(看起来像数据变旧了)。

### 5.1 本板的 `hello` 原文(MUST 逐字一致,除版本号)

```json
{"t":"hello","proto":1,"token":"","client_id":"st7735-160x80","role":"thin",
 "accept":["ui","data"],
 "display":{"w":160,"h":80,"depth":16},
 "charset":"ascii",
 "primitives":["rect","text","num"],
 "fonts":[16,32,48],
 "input":["key"],
 "limits":{"max_nodes":32,"max_json_bytes":1024,"max_text_len":20}}
```

> **2026-10-25 T6c/T6d 修正三处：`primitives` 去掉 `path`（解析器不支持，声明了
> 会让 daemon 发来整页被拒）、`fonts` 三档、`input` 有按键。**
>
> **`fonts` 的语义**：列出**能画的像素高度**，不是"支持缩放"。本板只有一套 8×16
> 字模，32/48 是整数倍像素放大（见 §4.4）。移植者的板子若有多种真实字模，同样在这里
> 列出实际高度即可，PC 端只看这个表。
>
> **`input` 的语义**：声明了 `["key"]` 才允许 PC 下发 `focusable` 节点。没声明就别
> 发——终端会画不出高亮，用户按了没反应。

> **2026-10-22 T5.1 修正(三处,均为"原文写错了"而不是"加功能")**:
>
> 1. **`v` → `proto`**。PROTOCOL §5 的字段名是 `proto`,daemon 也只读 `proto`;
>    本文原来的 `v` 从来没有被任何一端读过。按 §0"与 PROTOCOL 冲突以 PROTOCOL 为准"。
> 2. **补 `token`**。daemon 的 `_check_hello` 要求 token 匹配,否则回 `deny bad token`
>    并断连。T5 阶段先发空串(daemon 需 `--lenient` 启动);token 入 flash 是 T5.6,
>    它要动配置页与存储格式,不与链路改造混在一张卡里。
> 3. **补 `accept`**。daemon 只在 `client.accepts("ui")` 为真时才发 `ui`,
>    不带这一项 = 连接正常、只收到 catalog、然后再无下文。
>
> **2026-10-23 T5.6 已完成**：token 进了 flash（记录 `ver = 2`，见 `creds.rs`），
> 配网页多一个 `Daemon token` 输入框（留空 = 保持已存的），`hello` 的 token 从存储里取
> （`LINK hello tx n=304` = 288 + 16）。**严格 daemon（不带 `--lenient`）现在能直接接受**；
> token 不对时 daemon 回 `deny bad token`，板上打 `BOOT LINK fail` 并把 LINK 那行画成红色
> （帧 CRC `0x1EFEB12B`）。
>
> 逐字节原文钉在 `panel-core/src/wire.rs::HELLO`,由 `wire::tests` 校验形状、
> 上限与三个必需字段--**以那份常量为准,本节只是它的人读版本**。

- `fonts:[16]` 是**字高**(8×16 点阵),不是字宽。
- `input:[]` 表示没有输入设备 → daemon MUST NOT 下发 `focusable` 节点。
- 阶段4 起追加 `"widgets":["line"]`。
- **T6 起追加 `"layout":{"ver":<n>}`**(设备当前生效的布局版本,未实现)。
  没有它,PC 连上后无法判断设备是不是已经有这一版,只能无脑重推;
  而设备侧"同一 ver 不写 flash"(S-4)也就无法跨重启成立。

### 5.5 输入与事件上报(2026-10-22 新增)

> 需求原话:"电脑端关于设备的指令只能收到设定好的具体文字,因为电脑其实知道'第 3 页的第二个按键'代表'关机',设备发过来的就是'第三页的第二个按键'。"

| # | 规则 |
|---|---|
| I-1 | 固件 **MUST NOT** 存任何语义:没有按钮标签、没有动作名、没有"关机"这三个字。它只知道"一共有几个可选项、现在选的是第几个" |
| I-2 | 上报形状固定为 `{"t":"event","k":"key","id":"focus","v":<n>,"scene":<i>}`。**序号 1 基**(PROTOCOL §11.5),设备内部若用 0 基数组,出线前加一,全工程只允许在这一处换算 |
| I-3 | `scene` 是本板 MUST 带的字段:`ui` 切换在途时,不带页号的按键会被算到错的一页上,而 event 不重传、无法补救 |
| I-4 | 焦点越界 MUST 按 PROTOCOL §11.5 处理:收到新 `ui` 后 `焦点 >= 项数` → 焦点 = 1 |
| I-5 | 显示**本地页**时按键 **MUST NOT** 上报:那是设备自己的解释(翻页/进出),PC 不需要也不应该知道 |
| I-6 | 固件 **MUST NOT** 实现危险动作(关机、重启以外的系统操作)。"重启"只接受 `cmd` 的 `reboot`,且是 PC 端显式下发;危险操作一律在 PC 侧二次确认 |

**焦点高亮需要几何,这是 T6 的硬需求**:`ui` 解析时 MUST 额外保存一张 focus 表
(项数 + 每项的 `x/y/w/h`,≤32)。没有它,按键在屏上是**隐形**的--人按了没反馈,
而串口一切正常,属于最难查的那类问题。

这台板子 `hello.input = []`（无输入设备）时,daemon MUST NOT 下发 `focusable` 节点；
L1 把按键装上后改为 `["key"]`，**这一项变更与 L5 同时生效**，不能提前改。

## 6. 持久化

| # | 规则 |
|---|---|
| S-1 | 两扇区 A/B + 头部 `magic("PCFG") / ver / seq / crc32 / len`;写入先写非活动扇区 → 校验 → 再切换 `seq` |
| S-2 | 掉电在任意一步,下次上电 MUST 能回退到上一个完整版本(不允许"两份都坏") |
| S-3 | `data` 值 **MUST NOT** 写 flash(协议 §13) |
| S-4 | 只在"应用"(`ui.ver` 变化)时写一次;同一 ver 重复收到不写 |
| S-5 | key 用前缀分组:`wifi/`(ssid、psk)、`local/`(本地设置)、`ui/`(布局)、`diag/`(崩溃计数等) |
| S-6 | 布局存**二进制节点表**,不存 JSON 原文 |
| S-7 | CRC 校验失败 → 视为无布局 → 兜底页 + 向上位机要一份新的 |
| S-8 | **两组 A/B 独立**:凭据一对扇区、布局一对扇区,各自 `seq` 各自回退 |
| S-9 | 同一套"写非活动扇区 → 读回校验 → `seq` 定胜者"代码服务两组,**不许各写一份** |
| S-10 | 开机 **先读布局画上屏,再联网**;布局读不出来才用兜底页 |

### 6.1 本板的扇区划分

`nvs` 分区 `0x9000..0xF000`(6 × 4 KB),WiFi 以 `nvs_enable:0` 初始化,驱动不碰它。

| 用途 | 扇区 A | 扇区 B |
|---|---|---|
| 凭据(`creds`) | `0x9000` | `0xA000` |
| 布局(`saved`) | `0xB000` | `0xC000` |
| 空闲 | `0xD000`、`0xE000` | — |

移植者需要**两组共四个空闲扇区**;只有两个的话,布局可以和安全要求较低的配置共用一组,
但**不能和凭据共用**——一次布局保存失败不该让板子变砖。

### 6.2 扇区帧格式(两组共用)

```
off  len  what
  0    4   magic "PCFG"
  4    1   ver = 1
  5    2   len = payload 长度(0..=1024)
  7    4   seq,每次保存 +1
 11    4   crc32(header[0..11] || payload)
 15    n   payload
```

**两条保证**:
1. **帧是全有或全无**:`parse` 只在 CRC 覆盖了 `len` 声明的每一个字节时才接受。
   写一半掉电读回来是"不存在",不是"半个真相"。
2. **新的赢,而"新"看 `seq` 不看位置**:所以可以擦非活动扇区、写完校验、再靠 `seq` 切换。

### 6.3 布局 payload 格式(`S-6` 的二进制节点表)

```
off  len  what
  0    4   magic "PUI1"
  4    4   ver,来自 daemon 的 ui.ver
  8    1   scene 序号
  9    2   背景色 RGB565
 11    1   节点数(0..=32)
 12    n   节点,每种 type 只写自己的字段
 ..    4   crc32(覆盖前面全部字节)
```

每个节点:`kind u8 | x i16 | y i16`,之后按 `kind`:

| kind | 后续字段 |
|---|---|
| `rect`(0) | `w u16` `h u16` `colour u16` `border_flag u8` [, `border u16`] |
| `text`(1) | `size u8` `colour u16` `text_len u8` `text[len]` |
| `num`(2) | `size u8` `colour u16` `dec u8` `id_len u8` `id[len]` `unit_len u8` `unit[len]` |

**为什么按类型裁剪而不是定长**:定长每个节点约 59 B,32 个 = 1888 B,超过 1024 B
的扇区 payload 上限;按类型裁剪后最坏情况 **1008 B**,刚好放得下。

**`interval_ms` 故意不存**:它是 `catalog` 的属性,不是页面的属性。开机时还没有
catalog,留 0 = "永不过期";而值表本来就是空的,每个 `num` 都画 `--`——正是
协议 §22.3 说的"没 PC 时的样子"。

**验收(移植者必做)**:
- 存一页 → 读回 → **渲染出的帧 CRC 相同**(只比字段会漏掉颜色取整错误)
- 翻转任意一个字节 → 必须拒收
- **每一个截断前缀**都必须拒收,不能半解码

### 6.4 观察通道(串口不可用时的取证顺序)

本板实测:CH343 在 WiFi 电流尖峰时整块掉出设备树,**WiFi 启动之后的串口日志全部丢失**。
所以固件验收按可靠性排序:

1. **flash 回读**(`espflash read-flash` + 解析)—— 证明写进去的是什么
2. **玻璃**(人眼)—— 证明画出来的是什么
3. `cargo test` / PC 侧 parity —— 证明纯逻辑
4. 串口 —— **只在 WiFi 起来之前,或串口能撑过启动时**才可信

> 一条踩了七次的坑:**"没有日志"不等于"没有行为"**,除非先证明日志通道整段是通的。

### 7.1 启动横幅(MUST,每次上电一行行打完)

=== st7735 160x80 fw 0.1.0 (git a1b2c3d) ===

| E6 | 链路断开 | `link_down` |
| E7 | WiFi 连接失败(含原因码) | `wifi_fail` |

实现建议:用 `esp-println`(0.15,独立于 esp-hal 版本,只要求 critical-section)。

### 7.4 链路与角标行(阶段2 起,逐字可钉)

```
LINK tcp peer=<ip>:<port>      将尝试连接
LINK up                        socket 建立(不代表握手成功)
LINK hello tx n=<bytes>        每次新建连接后发 hello
LINK catalog n=<count> ver=<n>  握手完成(唯一会清零退避阶梯的事件)
LINK deny reason=<text>        daemon 自己的理由(bad token / proto mismatch)
LINK ping                     收到 ping 并已排队 pong
LINK unknown kind=<name> n=<k>  未知消息种类(W7)
LINK silent ms=<n>             15s 无字节(SPEC L-1)
LINK lost idle=<ms>            socket 结束,附最后静默时长
LINK fail reason=<Name>        连接失败,用库的变体名而非自编数字
LINK backoff ms=<n> tries=<n>  重连前等待(SPEC L-2)
BADGE on|off                   LINK LOST 角标出现/消失
```

**为什么 `BADGE` 也要占一行**:角标是这块板**唯一自己决定画的东西**,而它最容易出的事不是
"不出现"(一眼能看见)而是"不消失"——夹在健康链路上的角标会让用户以为数据过期了。
脚本看不见玻璃,只能让板子自己说出来(T5.4,2026-10-23)。

## 9. 移植清单(换一块板子怎么干)

按顺序做,每一步都有可执行验收。**不许跳步**--跳了以后会分不清是底座错还是板级错。

| 步 | 做什么 | 产物 | 验收 | 估时 |
|---|---|---|---|---|
| **P0** | 跑通 `core` 的 host 测试 | 无 | `cargo test` 全绿(含 §4.5 向量) | 0.5 天 |
| **P1** | 写 `bsp/pins.rs` + `panel_<ic>.rs` | 点亮纯色/棋盘 | 屏上出现四个色块,位置正确 | 1-2 天 |
| **P2** | 静态帧配平 | `blit_rect` 整帧 + CRC 行 | PC 算的 CRC == 板上 CRC(`PARITY OK`) | 0.5 天 |
| **P3** | 串口哑终端(`<top>\|<bottom>`) | `link_uart` | 打一行字上屏,CRC 仍一致 | 0.5 天 |
| **P4** | `store` A/B | `store_flash` | 写入→断电→读回,内容一致;模拟写一半后能回退 | 1 天 |
| **P5** | 联网 + 配网页 | `link_tcp` + AP 页 | 手机连热点配置,重启自动连;断网 30s 回热点 | 2-4 天 |
| **P6** | 协议子集(`hello`/`ui`/`data`)+ 持久化 | 完整固件 | 与 `term_tk.py` 同源同画面;拔电重开布局还在 | 2-3 天 |
| **P7** | 折线(`line` + 环形缓冲 + 脏区) | - | 曲线 1Hz 滚动,断线不消失 | 1 天 |

**最小可用里程碑 = P2。** 只要 P0-P2 过了,这块屏就已经"能证明自己画对了",后面都是加功能。

### 移植者必须自己决定的五项(T6c/T6d 之后新增)

| # | 要定什么 | 本板的答案 | 定不了的后果 |
|---|---|---|---|
| 1 | **有没有按键** | 有,四个,GPIO32/33/25/26 | 没按键就 hello.input=[],PC 不会发 focusable 节点,页面只能只读 |
| 2 | **能画几种字号** | 16/32/48(单字模整数倍放大) | 谎报会导致 PC 发来画不出的字号,it_nodes 会改,但声明错了等于没改 |
| 3 | **有几组空闲扇区** | 4 个(凭据 2 + 布局 2) | 只有 2 个时必须决定布局和谁共用,但**不能和凭据共用** |
| 4 | **消抖窗口** | 20 ms(电平保持) | 太小=一次按键跳多格;太大=快速连按丢失 |
| 5 | **是否支持路径/折线** | 不支持(primitives 无 path) | 声明了但解析器没实现 → **整页被拒**,屏上一直显示兜底页 |

> 第 5 条是真实事故:2026-10-23 hello 声明了 path 而 ui::parse_node 没有
> 对应分支,daemon 发来的每一页都整页 reject,板子一直显示自检卡片,而所有日志
> 看起来都正常。现在有一条测试钉住:hello 承诺的 primitive 必须都能画。

### 移植者最容易踩的四个坑

1. **别信"看着一样"**:面板偏移/镜像(`MADCTL`)错了,画面也会"看起来正常"但 CRC 永远不等。
2. **SPI 字节序**:RGB565 发大端还是小端,取决于 `COLMOD` 与面板;先跑 P2 的色块确认。
3. **DTR/RTS 复位**:USB 串口芯片的 EN/IO0 反相电路会把人坑死(本板实测:EN 脉冲三成被吞;
   而且实时画面**根本不需要复位**,别为了"让它刷新"反复拉 EN)。
   **被吞的复位会把固件伪装成"死了"**:芯片停在 espflash 留下的 ROM 下载模式,串口一个字不出。
   所以任何依赖复位的验证脚本 MUST 重试(`check_parity.py` 现在是 4 次、听到启动日志才停)。
4. **flash 写入期间断网/断电**:A/B 扇区不是为了省事,是为了"应用时断电也能开机"。

## 10. 变更流程

1. 本文有版本号。破坏性变更(改 `hello` 字段、改格式化规则、改存储布局)MUST bump 次版本并写迁移说明。
2. **格式化规则(§4.5)任何改动,都 MUST 先改 CSV 向量,再改两侧实现,然后跑 `PARITY OK`。** 顺序反了就会陷入"到底哪边对"的拉扯。
3. 协议相关的一切以 `PROTOCOL.md` 为准;本文只做"落到固件上要怎么做"的细化,不得新增协议语义。
4. 实现与本文不一致时:要么改实现,要么改本文并写明理由。**不许"代码是代码,文档是文档"。**
